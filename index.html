Claude trong 5 phút

Các mảnh ghép bạn sẽ gặp khi dùng Claude, tóm tắt cho người mới — trước khi so sánh với các AI khác.

Vì sao cần biết trước khi làm?

Hiểu đúng các mảnh ghép này giúp bạn biết nên hỏi Claude trong Chat bình thường, hay cần dựng hẳn một Project/Skill riêng cho công việc đang lặp lại — quyết định đó ảnh hưởng tới cả 3 chặng sau.

AI phổ biến trong giáo dục: công cụ nào hợp việc nào?

Nhấp từng thẻ để lật xem điểm mạnh, rủi ro và tình huống phù hợp. Không có AI nào "tốt nhất" cho mọi việc.

Skill hay Project — dùng cái nào?

Một cách phân biệt nhanh trước khi bắt tay dựng sản phẩm ở Chặng 3.

Project: Claude cần đọc bộ tài liệu này mỗi khi làm việc.

Skill: Claude cần làm đúng quy trình này, cho ra đúng khuôn mẫu này, lặp lại nhiều lần.

Ví dụ hợp với giáo viên: ma trận đề, chấm theo rubric, tổng hợp khảo sát, chuẩn hóa hồ sơ chuyên môn → đây là việc của Skill. Cách đóng gói Skill nằm ở Chặng 3.

Công thức 6 phần để AI hiểu đúng việc

Một công thức duy nhất, dùng lại được cho mọi việc.

1Bối cảnh: bạn là ai, dạy lớp nào, việc lặp lại ra sao.
2Đầu vào: file, đề, dữ liệu nào đang có.
3Nhiệm vụ: AI cần làm chính xác điều gì.
4Đầu ra: hình thức, độ dài, cấu trúc mong muốn.
5Ràng buộc: điều không được làm, quy ước riêng của tổ/trường.
6Kiểm chứng: cách biết kết quả đúng, cần AI tự rà lại điểm nào.

Cách 1 — Dựng công cụ HTML

Một file HTML chứa nội dung, giao diện và hành vi tương tác — mở bằng trình duyệt là chạy, không cần server.

Công thức yêu cầu Claude

Đây là học liệu tôi đang dùng: [ĐÍNH KÈM]. Hãy dựng thành MỘT FILE HTML DUY NHẤT, mở bằng trình duyệt là chạy. NGƯỜI DÙNG: học sinh [LỚP], dùng chủ yếu [THIẾT BỊ]. MÁY CẦN: [chấm điểm / flashcard / game / biểu đồ / lưu tiến độ...]. AI CẦN: [giải thích lỗi / nhận xét / sinh bài tương tự...]. RÀNG BUỘC: - phần cốt lõi chạy offline; - responsive, chữ rõ, nút dễ bấm; - không viết cứng API key; - nếu dùng AI, để người dùng tự nhập key; - một file duy nhất, không phụ thuộc server riêng. KIỂM CHỨNG: - chỉ rõ cách test đáp án, điểm số và các trường hợp lỗi; - thêm nút tự kiểm tra nếu phù hợp.
Quy tắc vàng: HTML một file rất hợp để luyện tập, nhưng không phù hợp cho thi lấy điểm vì đáp án nằm trong mã nguồn phía người dùng.

Cách 2 — Đóng gói thành Skill

Hợp với việc lặp lại, quy trình ổn định, cần kết quả nhất quán theo quy ước riêng của tổ/trường.

1️⃣Làm thật một lần — hoàn thành qua hội thoại thường, ghi lại chỉ dẫn phải nhắc lại.
2️⃣Rút mẫu tái sử dụng — giữ quy ước, ngưỡng, cấu trúc đầu ra có giá trị lâu dài.
3️⃣Viết bản tối thiểu — không nhồi mọi tình huống tưởng tượng.
4️⃣Kiểm thử hai phía — một phiên biên soạn, một phiên dùng thật.

🚀 Đưa HTML lên mạng bằng GitHub Pages

1. Tạo tài khoản

Đăng nhập GitHub và tạo repository mới.

2. Đặt file

Đổi tên file chính thành index.html.

3. Upload

Add file → Upload files → Commit changes.

4. Bật Pages

Settings → Pages → Deploy from branch → main/root.

5. Chia sẻ

Mở đường dẫn Pages; có thể tạo QR để học sinh quét.

Lưu ý: Google Drive có thể phát file, nhưng link Drive không biến HTML thành website chạy trực tiếp. GitHub Pages phù hợp hơn để có địa chỉ web cố định.
